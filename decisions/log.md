## 2026-06-16 — Launch prep: apex domain solscaperetreats.com (root /) + sitemap/robots + secret audit

Repointed the site from the GitHub Pages sub-path (`/solscape-retreats/`) to the custom apex domain, served from root. **`astro.config.mjs`:** `site` → `https://solscaperetreats.com`, `base` → `/`, added `@astrojs/sitemap` integration (kept `output: 'static'`, `build.format: 'file'`). **Critical base-join fix (flagged, not silent):** confirmed this project's `import.meta.env.BASE_URL` has NO trailing slash and every internal URL uses the join `` `${base}/path` ``. With `base: '/'`, `BASE_URL` becomes `/`, so `` `${base}/css/styles.css` `` would render `//css/styles.css` — a protocol-relative URL the browser resolves to `https://css/...`, breaking CSS/JS/images/links site-wide. Fixed by normalizing at consumption in all 17 `.astro` files (every `src/pages`, `src/layouts/Layout.astro`, `src/components/Nav.astro`+`Footer.astro`): `const base = import.meta.env.BASE_URL.replace(/\/+$/, "");`. This yields `''` for root (→ clean `/path`) and is unchanged for any sub-path, so the `` `${base}/...` `` usages stay as-is. (Implementation note: sed/perl mangled the backslash in the regex literal on Windows; applied the edit via a Node script using `String.fromCharCode(92)` and byte-verified the result.) **New `public/CNAME`** (`solscaperetreats.com`, one line) persists the domain across `withastro/action` deploys (Astro copies `public/`→`dist/`). **New `public/robots.txt`** allows all + references `https://solscaperetreats.com/sitemap-index.xml`. **`.gitignore` hardened:** added `.env*`, `*.pem`, `*.key`, `*.p12`, `*.pfx` (the existing `*.env` missed `.env.local`/`.env.production`). **Security audit (filesystem, read-only):** CLEAN — no secret files, no real token-like content (only "passwordless" prose in CLAUDE.md), no `.env` present. **Verified:** `npm install` + `npm run build` pass (14 pages, sitemap-index.xml + sitemap-0.xml generated with apex-domain URLs); `dist/` grep shows zero `/solscape-retreats` refs, zero `//` double-slash paths (excl `https://`), clean root paths (`/css/styles.css`, `/images/greece/...`, `/retreats/greece`), home link `/`, `dist/CNAME` = `solscaperetreats.com`, `dist/robots.txt` with the Sitemap line. ## 2026-06-18 — Mobile date-badge clipping fixed (responsive `.dates-badge`, shared)

Resolved the badge-clipping flagged above. **Root cause (measured via Chrome DevTools Protocol at a true 375px viewport):** `.dates-badge` (`inline-block`, no `white-space` set) sits inside `.hero-content`, a flex item whose default `min-width: auto` blocked it from shrinking below its single-line max-content width — so the badge never wrapped and ran off the right edge under `.detail-hero { overflow: hidden }`. (Earlier headless `--window-size=375` screenshots were misleading: that Chrome build rendered at `innerWidth: 478` and cropped to 375, faking the clip; CDP `Emulation.setDeviceMetricsOverride` was needed to get a real 375px render.) **Fix (all inside the existing `@media (max-width: 768px)` block in `public/css/styles.css`, so desktop is untouched):** `.detail-hero .hero-content { min-width: 0; max-width: 100%; }` lets the flex item shrink to the viewport, and `.dates-badge` gets `white-space: normal` plus smaller `font-size: 0.68rem`, `letter-spacing: 0.1em`, `padding: 8px 16px`, `line-height: 1.7` for a tidy 2-line wrap. **Shared by design** — `.dates-badge` is also used on `past/croatia`, `past/spain` (even longer text), `past/tuscany`, so all benefit consistently. **Verified (CDP, true viewports):** at 375px `innerWidth == scrollWidth == 375` (zero overflow), badge 295px wide / left 40 / right 335 / wraps to 2 lines, nothing clipped; at 1280px the badge is unchanged (font 12px = 0.75rem, letter-spacing 0.14em, padding 10px 24px, single line). Build passes (14 pages); straight quotes. No git. Ships together with the hero-centering + blurb changes above.
